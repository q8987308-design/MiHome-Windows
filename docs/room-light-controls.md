# 房间灯光全开与全关

在左上角选择具体家庭，再选择具体房间，设备列表上方显示“灯光全开”和“灯光全关”。按钮旁标注可控制项目数及离线数量。选择“全部”家庭、“全屋”或“场景”时不提供批量控制；未知家庭或未知房间同样不能执行。

## 控制范围

- 纳入型号类别为 `light` 的灯具，以及型号类别为 `switch` 且名称包含“灯”“照明”“light”或“lamp”的开关。
- 跳过离线设备，不控制路由器、网关、插座、空调、窗帘或用途不明确的开关。
- 同一多键开关已有虚拟通道时，排除父设备，避免重复控制第一路。
- 先处理照明开关，再处理智能灯具；刚恢复供电的灯具可能暂时无法响应，此时如实报告失败，不自动重试。

“床头柜”“主开关”等名称本身无法确认用途，因此不会自动纳入。当前沿用上游以家庭名称和房间名称区分位置的模型；不同家庭或房间应使用可区分的名称。

## 执行与反馈

点击时冻结目标列表，通过现有串行后台队列设置明确的开/关状态，不使用切换动作，也不创建米家云端场景。执行期间禁止重复提交；切换房间不会改变已经排队的目标。

单台设备失败后继续处理其他设备，完成后汇总成功、失败和跳过离线数量。失败时保留原显示状态，并在状态提示中列出失败设备。复用轮询版本号，防止操作之前发出的旧轮询覆盖新状态。

## 启动

常规源码入口仍为 `run.py` 或 `start.bat`。

`launch.py` 额外提供 Windows 无控制台启动支持，并默认使用 `%LOCALAPPDATA%\MiHome-Windows` 保存应用数据，便于从官方便携版切换。显式设置 `MIHOME_DATA_DIR` 时沿用该设置。账号凭据仍由上游库管理，不随源码分发。
